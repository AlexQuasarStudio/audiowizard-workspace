# Финансы, выплаты и Smartcat — спецификация для Клода

Документ описывает модель, которая уже реализована в прототипе (`js/finance.js`,
раздел «Выплаты и Smartcat»), и требования на будущее. Его нужно сохранять и
развивать: часть поведения уже заложена, часть — задел.

## 1. Доли заказа

Сумма заказа `total` делится так:

| Доля | По умолчанию | Где хранится |
|---|---|---|
| Исполнители | их суммы `executors[].amount` | в заказе |
| Админ (маржа) | 25 % от `total` | `settings.finance.adminMargin` |
| Менеджер заказа | 10 % от `total`, но не выше остатка (менеджер прописывает свою оплату за заказ) | `settings.finance.managerFee` / `order.managerFee` |
| Остаток | `total − исполн. − админ − менеджер` | вычисляется |

При переходе в «Выполнено» начисляются все доли (`Finance.accrue`), при откате
статуса — полностью отменяются. Если сумма долей больше `total` — дефицит:
система показывает его в подтверждении выполнения, пишет уведомление админу и
требует осознанного подтверждения.

Маржа админа — и есть его выручка по всем услугам: по умолчанию 25 % (после
сброса приложения у всех услуг `margin: 25`).

## 2. Долги

Долг не хранится отдельной сущностью: это вычисление по выполненным заказам,
где не закрыты доли. В таблице заказов — маленький маркер «₽» у суммы и
фильтр «Долги»; разбивка по пользователям считается из `executors[].is_paid` и
`splitAccrual.manager.paid`. Отдельных колонок и сущностей нет.

## 3. Расписание выплат

По умолчанию: 1-е и 15-е число, 15:00 МСК. Полуинтервалы:

- с 1-го числа (включительно) по 14-е 15:00 МСК;
- с 15-го (включительно) по 1-е 15:00 МСК следующего периода.

Период определяет только дату выплаты. В саму выплату попадают **все
выполненные заказы с неоплаченными долями** — включая завершённые раньше
текущего полуинтервала. Любой заказ можно вручную убрать из выплаты
(`S.settings.payout.excluded`, по `order_id`) и вернуть обратно.

Настройка полностью доступна админу и менеджерам: дни, время, включение
автовыплат, ручная выплата, комиссия системы оплат. Исполнитель видит условия и
свой долг, а в подсказке — предупреждение о комиссии Smartcat (база 5 %, но она индивидуальна для аккаунта).

## 4. Платёжный провайдер (по умолчанию Smartcat)

- Аккаунт Smartcat привязывается к пользователю: `users[].ext.smartcat = { login,
  status, requestedBy, approvedBy }`.
- Привязать может админ/менеджер или сам исполнитель — тогда нужен подтверждающий
  (статус `pending` → `approved`).
- Через Smartcat получают оплату не только исполнители, но и менеджеры.
- Экспорт платёжных данных: `smartcat.payout.batch.v1` (JSON) — документы с
  языками, объёмом в словах, ставкой и суммой; суммы сходятся с долгами,
  комиссия вычитается, `net` — на руки.

### Будущее (заложить, не терять)

1. Самостоятельный вывод средств пользователями, в первую очередь исполнителями.
2. Оплата менеджеров через Smartcat (модель уже это допускает).
3. Если платёжный аккаунт не привязан: пометить «оплачено вне системы» может
   админ/менеджер или сам человек (с подтверждением).
4. Уведомление админу по расписанию (по умолчанию 15:00) о сумме, которую нужно
   завести на Smartcat; зачисление — на следующий рабочий день. Нужен
   производственный календарь РФ (праздники, переносы, выходные).
5. Альтернативные платёжные интеграции (не только Smartcat) — интерфейс
   `provider` с общим контрактом экспорта/подтверждения.
6. Глубина настройки: исключения по исполнителям, лимиты, согласование крупных
   сумм, история и повторные выплаты.

## 5. Код

- `js/finance.js` — `Finance`: `split`, `accrue`, `debts`, `pending`,

- `js/crm.js` — начисления при смене статуса, предупреждение о превышении,

- `js/app.js` — раздел «Выплаты и Smartcat» в настройках.
- `js/ui.js` — `Cols` (ширины колонок).


## 6. Универсальность провайдера (важно для Клода)

Название, комиссия и включённость провайдера НЕ должны хардкодиться в интерфейсе:
они берутся из `settings.integrations.payout = { key, name, commission, enabled, perUser }`.
Сейчас это `smartcat`, но смена или отключение провайдера — правка настройки, а не кода.
Исполнитель видит только свой аккаунт; список чужих аккаунтов и служебная статистика —
только для админа и менеджеров. Комиссия индивидуальна для аккаунта, поэтому в UI
пишется «комиссия <провайдер> — N % (индивидуальна)».
